# 行動の選び方

`config.action_mode` で、環境に出す1手の出どころが分かれる。分岐は `agent.select_action` にある。

- `"candidate"` は `policy.CandidatePlanner`。行動空間から長さ `horizon` の列を作り、期待自由エネルギー（EFE）の和が最小の列の先頭だけを実行する。
- `"policy"` は `policy.PolicyNet`。現在の潜在状態から行動分布を1つ出し、そこから1手をサンプルする。

列を想像の中で進めて EFE の和にする関数は `efe.evaluate_action_sequence` で共通である。違うのは、その列を誰が作るか、そしてその作り方に学習する重みがあるかである。

式は [数式.md](数式.md) の「期待自由エネルギー」「行動の選び方」にある。このファイルは、コードが1ステップのあいだに何をしているかを書く。

## 共通していること

環境ループの1ステップは `train.collect_episode` が行う。

1. 直前の潜在状態、直前の行動、今の観測から `agent.get_posterior_state` が事後状態 `(deter, stoch)` を1つ作る。エピソード先頭はゼロ状態と零行動から始める。
2. `select_action` がその事後状態から行動を1つ返す。
3. 環境の `step` に渡し、観測・報酬・終了を受け取る。

想像に使うのは RSSM の `prior` だけである。`prior` は直前の状態と行動から GRU の `deter` を進め、観測なしで次の `stoch` をサンプルする。報酬デコーダはその状態の特徴から報酬の平均を出す。

1歩の EFE は `efe.compute_efe_from_parts` で、小さいほどよい。

```
G = pragmatic_weight * (-予測報酬の平均) - epistemic_weight * 情報利得
```

情報利得の既定（`efe_mode="entropy"`）は、その歩の `stoch` の事前エントロピーである。`"kl"` のときは、想像した観測の平均をエンコーダに戻し、戻したあとの事後と事前の KL を使う。`train` は `"entropy"` のまま進む。

長さ `horizon` の列の評価値は、各歩の `G` の単純和である。`Config.gamma` はこの和に掛かっていない。

## 候補モード

`CandidatePlanner` は Equinox のモジュールではない。学習する配列を持たない。`plan` が呼ばれるたびに、次の3つをその場で行う。

### 1. 候補列を作る

`policy.sample_action_sequences` が `(N, horizon, action_dim)` を返す。`N` は `config.candidate_count`、`horizon` は `config.horizon`。`train` では `N = 81`、`horizon = 4`。

離散行動（第一段は one-hot の3値）では、全列の数 `n ** horizon` が `N` 以下なら全列挙する。3値でホライズン4なら `3^4 = 81` なので、`train` の離散設定は取りうる列をすべて作る。各時刻は one-hot である。全列が `N` を超えるときは、各時刻のインデックスを一様に引いて one-hot にする。

連続行動では、行動の下限と上限のあいだから一様に `N` 本引く。第一段の連続行動は速度そのもので、範囲は `[-max_speed, max_speed]`。近い列を寄せる、前回の勝者の周辺を探す、といった操作はない。

### 2. 各列の EFE 和を計算する

`efe.evaluate_action_sequences` が列ごとに `evaluate_action_sequence` を `vmap` する。1本の中では `scan` で次を `horizon` 回繰り返す。

1. 今の潜在状態と、その時刻の行動で `rssm.prior` を1歩進める。
2. 進んだ状態の特徴から報酬デコーダの平均を取る。
3. `efe_mode` に応じて事前エントロピー、または想像観測をエンコードし直した KL を取る。
4. その歩の `G` を足す。

開始状態は、今の事後状態である。想像の途中で環境の観測は使わない。

### 3. 最小の列の先頭だけを実行する

`_plan_with_seqs` が `argmin` で和が最小の列を選ぶ。環境に渡すのはその列の0番目だけである。残り `horizon - 1` 手は捨てる。

次のステップでは、実行した1手の結果の観測で事後状態を更新し、候補の生成からやり直す。前のステップで2番目以降に並んでいた行動は、次の計画の候補に残らない。

`select_action` が返す付帯情報は、選んだ列の EFE、全候補の EFE 平均、候補数である。

### 候補モードは行動を学習しているか

状態から行動への写像は学習しない。

`CandidatePlanner` に重みはない。`select_action` の候補分岐は `agent.policy` を呼ばない。候補の評価でも `PolicyNet` の出力は使わない。勝った列を次のステップの初期値にしたり、勝った行動の確率を上げたりする更新もない。どの列が選ばれたかは、そのステップの `argmin` で終わり、パラメータとして残らない。

候補の評価が意味を持つのは、その前に世界モデルが「行動を入れたとき次の潜在状態と報酬がどうなるか」を学習しているからである。学習されるのは次の部品で、いずれも行動そのものではない。

| 部品 | 行動との関係 |
|---|---|
| RSSM の `prior` | 行動は GRU への入力。次の `deter` と `stoch` の予測が行動に依存する |
| 報酬デコーダ | その予測状態から報酬の平均を出す。EFE の実用項はここの符号反転 |
| 観測デコーダ | `efe_mode="kl"` のときだけ、想像観測を作るために使う。`"entropy"` では候補評価に出てこない |
| エンコーダ | 実データの事後更新と、`"kl"` の情報利得で使う |

世界モデルの損失（`agent.world_model_loss`）は、観測の再構成、報酬の対数尤度、事前と事後の KL の和である。行動は系列の条件として入るだけで、損失の中に「この行動を出せ」という項はない。勾配もエンコーダ、RSSM、二つのデコーダに乗り、方策ネットの勾配はゼロのまま残る。

`train` では、この世界モデル学習はランダム行動の軌道に対して行う。候補モードで動かす時点では、方策の重みは初期値のままである。

`train` は候補モードで集めた10エピソードをリプレイバッファに足す。その直後に世界モデルの更新はもう走らない。足した軌道が使われるのは、次の方策学習で、想像を始める事後状態を切るときである。候補プランナーの手続きは、そのデータがバッファに入っても変わらない。

まとめると、候補モードが行動について持っている知識は、世界モデルの中の「この行動を取ると、こう遷移し、この報酬が予測される」という予測だけである。毎ステップ、その予測で候補を採点し、最小の先頭を出す。

## 方策モード

`PolicyNet` は潜在特徴 `feature = [deter, flat(stoch)]` から行動分布を出す MLP である。`Agent.create` は行動モードに関係なく、このネットを最初から持っている。重みが行動に使われ、更新されるのは方策モードに入ってからである。

### 分布の形

行動キーは1つだけを想定している。

離散では、出力次元が行動の個数で、`distrax.OneHotCategorical` のロジットになる。サンプルは one-hot である。

連続では、出力を平均と標準偏差に分ける。平均は `tanh` で行動の下限と上限のあいだに押し込み、標準偏差は `softplus` に `min_std`（`1e-4`）を足す。分布は `distrax.MultivariateNormalDiag` である。

### 学習でやっていること

更新は `agent.policy_loss` を `make_policy_step` が1回分適用する。`train` では30エポックである。

開始状態は、バッファの実系列を RSSM の `observe` で通した末尾の事後状態である（`train.extract_start_states`）。ゼロ状態から想像すると、集めた軌道と無関係な未来になるため、末尾を使う。この開始状態には `stop_gradient` が掛かる。

各開始状態から、観測なしで次を `horizon` 回繰り返す。

1. 今の特徴から `PolicyNet` の分布を作り、行動を1つサンプルする。
2. その行動で `rssm.prior` を1歩進める。
3. 進んだ状態の予測報酬と事前エントロピーから、その歩の EFE を出す。

方策損失の中の EFE は、情報利得に常に事前エントロピーを使う。`epistemic_kl` は渡さない。`train` は方策学習の前に `efe_mode` を `"entropy"` にしている。想像の各歩で観測デコーダとエンコーダを通す KL は、方策学習には入らない。

損失の形は離散と連続で違う。どちらも、EFE が大きい想像ほど方策にとって損になる向きである。

離散のサンプルからは行動を経由して勾配が戻らない。各歩の EFE を `stop_gradient` で定数にし、その歩の対数確率に掛ける。EFE が大きい行動ほど、その行動の対数確率を下げる勾配が強くなる。

連続のサンプルは平均と標準偏差から再パラメータ化されている。損失はホライズン分の EFE の和そのもので、勾配は行動を経由して方策の平均と標準偏差へ戻る。途中の RSSM と報酬デコーダは、次の段落のとおり更新されない。

どちらの損失からも、`actor_entropy`（既定 `1e-4`）を掛けた方策エントロピーの和を引く。最小化すると、分布のエントロピーを大きくする側に働く。

`make_policy_step` は損失を計算する前に、エンコーダ、RSSM、観測デコーダ、報酬デコーダへ `stop_gradient` を掛ける。勾配が残るのは `PolicyNet` の配列だけである。想像の中で EFE が行動を通って世界モデルの計算グラフに入っても、そちらの重みは変わらない。

### 実行でやっていること

`select_action` の方策分岐は、想像のロールアウトを回さない。EFE も計算しない。現在の事後状態の特徴から分布を1つ作り、`dist.sample` で1手を引いて環境に渡す。付帯情報の `efe` は `None` である。

学習中にホライズン分の EFE 和が小さくなるよう分布を動かしてあり、実行時はその分布を1回サンプルするだけである。候補モードのように、出す直前に複数の未来を比べる処理はない。

## `train` の中での順番

`train.train` は両方を続けて走らせる。候補の評価が終わってから方策の学習が始まる。

1. 一様な行動でエピソードを集め、世界モデルだけを更新する。
2. `action_mode="candidate"` で10エピソード行動する。ここで方策の重みは更新しない。集めた軌道はバッファに足す。
3. バッファ上の事後状態を開始点にして、方策ネットだけを更新する。
4. `action_mode="policy"` で10エピソード行動する。

同じ `collect_episode` が 2 と 4 の両方を担当する。`config.action_mode` が `"candidate"` か `"policy"` かで、`select_action` の分岐だけが変わる。
